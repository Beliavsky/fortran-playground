# Stdlib systems: retained unsuccessful consumers

All probes use stdlib commit 58eb9133966c2797e0593281169ef57c43eccc1d and the hosted GNU Fortran 16.2.0 sandbox with FPM 0.12.0. Each JSON record saves the exact normalized UTF-8/LF source hash, pin and full build/run result. Libraries were reused.

The generalized-eigenproblem probe incorrectly required Euclidean unit norms. This was a consumer error: GGEV instead scales each vector so max(abs(real(v))+abs(imag(v)))=1. The pinned implementation documents this at src/stdlib_lapack_eigv_gen.f90 lines 5740..5790. The attempted corrected consumer retained all independent eigenvalue and left/right residual checks and checked the actual normalization. It also failed, as explained below.

The CG, PCG and BiCGSTAB dense convenience wrappers compiled but segfaulted at runtime. The cause has not been established. Those wrappers use internal procedure callbacks; their exact probes are retained rather than being presented as working sandbox examples. Separate checked drivers use the public solver kernels with ordinary module procedures for callbacks and explicit caller-owned workspaces. Those kernel results do not verify the failed convenience wrappers. No stdlib numerical source was patched.

The corrected GGEV-norm consumer also failed. A diagnostic probe retained as generalized-eig-complex-vectors.f90 shows eigenvalues -1.0000000000000002+0.25000000000000006*i and its approximately conjugate partner with a slightly different imaginary component. The exact-conjugacy comparison is false; returned eigenvectors have zero imaginary components, and the independent right-eigenvector residual is large. The pinned assign_real_eigenvectors_dp reconstruction routine at src/stdlib_linalg_eigenvalues.f90:2585..2617 tests exact equality of already scaled eigenvalues. This is a likely cause, not a patched or fully diagnosed fix. Consequently only the generalized eigenvalue-only API is demonstrated by the published checked driver; returned generalized eigenvectors remain unverified/failed for this probe.
