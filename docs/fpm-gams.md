# GAMS classifications for selected packages

All 159 selected packages have one or more top-level assignments from the [NIST GAMS classification scheme](https://gams.nist.gov/cgi-bin/serve.cgi). The assignments are maintained by the playground; they are not NIST or package-author endorsements.

140 packages also have immediate subclass assignments. The saved taxonomy contains 96 immediate subclasses, retrieved from the linked NIST parent pages on 2026-10-28. B, O, P, Q, and Z have no published immediate subclasses. Broader assignments are retained where an immediate subclass does not fit or requires further review.

These discovery assignments are based on saved descriptions, topics, bundled examples, and upstream documentation where reviewed. A class indicates relevant package functionality, not coverage of every problem in that class. This is not a routine-by-routine verification. Detailed procedure mappings, problem-specific drivers, and comparative benchmarks remain future work.

## Searching

Choose **GAMS class** in the hosted or main local FPM page. It combines with the text search, Category, topic-source choice, and sort order. Choose **All classes** to clear it. Choose **Subclass** after selecting a parent. A parent includes all packages assigned under it; a subclass matches only explicit reviewed assignments, not packages known only at the parent level. The explicit search syntax `GAMS D` (or `GAMS: D2`) uses the same hierarchy; ordinary searches also include the assigned class descriptions. GAMS classification is independent of the GitHub-only topic setting.

Selected package details link to the NIST definitions. Other collections are not comprehensively classified: the translated R collection hides the filter, and the retained All collection includes assignments only for selected packages. Unclassified entries are excluded when a class is selected. Changing collections clears the class filter. Browsing and filtering do not submit jobs or contact NIST; opening a definition link visits NIST.

## Classification choices

- Random-number generators use **L**, whose L6 subclass is random number generation. [M](https://gams.nist.gov/cgi-bin/serve.cgi/Class/M) is reserved for simulation and stochastic modeling; a stochastic optimization algorithm is classified under G rather than M just because it uses random numbers.
- Least-squares approximation and smoothing can appear under **K**, alongside **D**, **G**, or **L** when the package also provides linear solvers, optimization, or statistical regression.
- Numeric expression parsers use **C/N**. Evaluating strings is not evidence of symbolic algebra under **O**.
- **P** includes geometric operations and graph algorithms; **N** includes graph storage and other data structures.
- **R** includes precision-support constants, error handling, and date/time services. Domain-specific physical constants and thermodynamic properties use **Z**.

- Date/time services retain R: there is no immediate date/time subclass. General programming support can retain S without being forced into transformation, static analysis, or dynamic analysis.
- H1 includes numerical derivative APIs, including automatic differentiation; this assignment does not imply finite-difference implementation.

## Procedure mappings and drivers

For deeper classifications, identify the actual module and procedure at the pinned revision. Check author-provided examples and tests before writing a driver. Reuse or adapt them when suitable, recording the original path, revision, license, and modifications. A shared mathematical problem and external accuracy criteria are still needed for comparisons across packages.


## Maintaining assignments

Edit [gams.json](../fpm_catalog/gams.json). Keep assignments separate from GitHub topics and playground topics, and add an entry whenever a selected package is added. Use multiple classes only for functionality the package provides. Keep root assignments in `packages`, immediate assignments in `subclass_assignments`, official labels/parents in `subclasses`, and qualifications in `review_notes`. A child assignment must have its parent assigned.

```text
python xpackage_gams.py
python xfpm_examples.py
```

The first command validates complete catalog coverage and regenerates this page. Use `python xpackage_gams.py --check` to check it without writing. The second regenerates the public catalog assets. Both commands are offline; neither builds packages nor redeploys the execution service. Class labels in the HTML filter and generated subclass module are checked against this metadata by tests.
