# Precompiled FPM packages

The hosted FPM playground has **58 precompiled packages in 24 categories**, with search and category filters above the **Available packages (GNU Fortran 16)** selector. Each entry has a one-line description and an editable example main program. **Load package** selects GNU Fortran 16.2.0, the exact source revision, and **My main program**. Loading never submits a job. Only builds verified and advertised by the deployed service can be selected.

## Selection and versions

The expanded selection balances popularity, reuse, and useful exploration tasks. It covers numerical methods, data formats, dates, files, processes, command-line tools, and containers, with a short checked consumer program for every entry. A survey of 400 accessible FPM manifests from [Fortran-packages-list](https://github.com/Beliavsky/Fortran-packages-list) found 33 projects referencing test-drive, 13 pyplot-fortran, 12 json-fortran, 11 stdlib, 7 toml-f, and 6 M_strings. These are direct dependency counts in this sample, including development dependencies; they are not ecosystem-wide usage measurements. Repository stars were also considered, with stdlib, json-fortran, and pyplot-fortran among the more popular choices. LAPACK was requested explicitly; FFTPACK and roots-fortran round out common numerical work. See [survey evidence](fpm-catalog-selection.json).

The second expansion adds 23 packages, taking the catalog from 35 to 58 while adding approximately 35 MiB of logical library artifacts. It adds automatic differentiation (Differentia), functional array operations, hash tables, text tokenization and regular expressions, several optimization methods, special functions, grid interpolation, rational arithmetic, colors, and orbital mechanics. Functional-fortran and the Fortran Astrodynamics Toolkit are among its more popular libraries; testing helpers, kinds, fhash and M_framework are also referenced by other packages in the manifest sample. Selection is based on utility and a working consumer example as well as popularity.

[fpm_catalog.json](../fpm_catalog.json) records exact commits, archive checksums, license declarations, descriptions, and the dated popularity/reuse sample. The stdlib entry uses its pre-generated `stdlib-fpm` branch rather than requiring Fypp during submissions. It is a pinned snapshot, not a promise to track the latest stdlib release. Upstream sources and license files remain in each package image. License declarations are recorded per package; they vary, including GPL for ferror and fortran_test_helper. Fortran-primes declares MIT in its manifest but its source headers also identify CC-BY-NC-4.0 components. The kinds manifest uses a placeholder license string; its LICENSE file specifies BSD-3-Clause. The short [example programs](../fpm_catalog/demos) live in this repository; `python xfpm_examples.py` regenerates the browser catalogs.

## How reuse works

Each catalog library is built ahead of time using GNU Fortran **16.2.0**, FPM **0.12.0**, and the same debug profile and compiler flags as normal package jobs. A separate immutable image contains its sources, dependency revisions, module files, object files, and library archive. Selecting that exact repository/commit in **My main program** mode reuses the image and compiles/links your edited main program. Results explicitly say whether the library was reused.

Debug symbols are removed from precompiled dependency objects and archives to keep linked executables within the existing 16 MiB file limit. Runtime checks remain enabled; your main program retains its debug information. Backtraces inside a cached dependency may therefore have less detail than a local debug build.

All 58 packages passed the changed-main sandbox check, including a returned PNG for pyplot-fortran. The final measured compile/link stages took about 0.2 to 2.7 seconds. Their logical library artifacts total about 718 MiB; this excludes compiler layers, sources, and main executables and is not a compressed storage or billing measurement. See [the recorded validation](fpm-precompiled-validation.json).

Every job receives its own disposable filesystem copy. User code cannot update the published cache or another user's files. There is no shared writable build directory or package download during a cache hit. The normal job admission, CPU/memory bounds, network restriction, build/run timeouts, and output limits still apply. A changed main still needs compilation/linking; precompilation does not remove compiler/package limitations.

Other compilers, unlisted revisions, arbitrary package URLs, and the package's own Build/Run/Test workflow continue to use clean builds. A cache is never reused across compiler versions or workflows. One catalog package is selected at a time; combining several catalog dependencies is outside this first version. The ordinary source playground and local tools do not load these images.

The hosted Python runner also benefits automatically when `--fpm URL --revision COMMIT --main FILE` selects a catalog pin with GNU 16. Its output reports library reuse, including in terse mode.

## Build, verify, and deploy

Use an authenticated Python environment containing [requirements-fpm.txt](../requirements-fpm.txt). From this repository root:

```powershell
python -X utf8 xprecompile_fpm.py
```

This builds and publishes package images, without changing the running API. First builds of LAPACK and stdlib can take several minutes. Offline prebuilds have a separate one-hour build allowance, 2 CPUs, and 4 GiB memory; this does not increase the limits for visitor jobs. They run without network access or secrets and compile as an unprivileged user. Sources are downloaded, bounded, and checked before entering the sandbox.

Before publication, the builder starts another sandbox with the ordinary public resource limits, changes executable Fortran statements in the main program, and checks both its output and reuse of library artifacts. Plotting must return a PNG. A failed package stops a complete catalog build from reporting success. Reports and reusable image references are stored locally in ignored `.fpm-audit-cache/precompiled.json`. Published libraries can also be recovered by their deterministic names when that local report is missing.

```powershell
python -X utf8 xdeploy_fpm.py --owner-secret p2f-owner
```

The deployment command builds/verifies the catalog automatically and reuses matching images from its local report after rechecking them. It advertises only verified images. Omit `--owner-secret` on an independent fork, or supply your own secret name. Other supported compiler images are built/verified as before. A fork uses its own Modal account and images.

For a smaller first deployment, use `--packages fortran-lapack test-drive toml-f`. To deploy the original clean-build-only service, use `--without-precompiled`. Both deployment options also accept the existing `--compilers` argument. A standalone prebuild can use the same `--packages` subset and an optional `--report PATH`.

After deployment, `/api/health` lists enabled `precompiled` package IDs, exact revisions, and `gfortran`. Publish the static page through the repository's normal GitHub Pages workflow. A new page connected to an older service keeps the existing examples and custom URLs usable and explains that precompiled packages have not yet been deployed.

Package updates require an explicit new pin/checksum and rebuild of that package. Transitive dependencies are locked by repository, exact commit, and archive checksum; floating upstream branches are not re-resolved during a catalog build.

`fpm_build_recipe.json`, the GNU build flags, and the build/preparation helpers determine the library recipe. A package's identity contains only its source pin, dependency locks, and recipe. Descriptions, categories, stars, other catalog entries, browser code, API code, worker updates, and other compiler installers do not invalidate the compiled library. Changes to the compiler or relevant build inputs require new libraries.

Published library images and current worker images are separate. Deployments overlay updated worker code onto each private library image when needed, then verify an edited main before publishing its runnable image. Workers validate the immutable package pin directly, so catalog-only edits do not require updating existing worker images either. No library compilation occurs for that overlay. Every deployment still runs short verification jobs. This cache-layout transition requires one initial rebuild; subsequent unrelated changes preserve the compiled libraries.

The optional pyplot module is precompiled alongside libraries that do not already supply it, allowing a user to add a plot to a main without regenerating a large dependency archive. No source compilation or cache construction happens during service startup or a visitor's request.


## Additional validation and limits

[The cache-reuse check](fpm-cache-reuse-validation.json) changed package metadata, added an unrelated catalog entry, changed the worker identity, and started without a local report. It recovered the existing published library and ran a changed main with zero library-build calls. The earlier refresh of the original 35 worker images also made zero library-build calls.

[The cached plotting check](fpm-cached-plot-validation.json) added a pyplot plot to the stdlib consumer and returned a PNG without rebuilding its library. Ordinary mixed C/Fortran package Build, Run, and Test passed with the updated GNU worker too.

Verification covers the supplied consumer examples, rather than every routine or compiler. The QUADPACK example uses its 15-point Gauss-Kronrod rule. During testing of this pinned build, the 61-point rule returned approximately 0.333333332987796 for the integral of x squared from zero to one, despite requesting 1e-10 accuracy. That discrepancy remains a recorded numerical limitation; the 15-point example passes its explicit accuracy check.

Simulated-annealing was deferred because its current manifest requires newer FPM syntax; older releases require external BLAS/LAPACK. The newly considered CODATA and SpecialMatrices manifests require registry/metapackage dependencies, which this preparation path does not yet support. Polyroots-fortran was not added because it needs external BLAS/LAPACK libraries absent from the current sandbox image. FACE and PENF source archives failed the existing strict archive extraction rules. See [candidate selection and exclusions](fpm-catalog-selection.json). Existing support for arbitrary URLs, other compilers, and clean package workflows remains available under its normal constraints.

To refresh the public measurements after editing examples or adding packages, run `python xprecompile_fpm.py --validation-report docs/fpm-precompiled-validation.json` without `--packages`. The report records each example source hash and rejects examples edited after verification.
